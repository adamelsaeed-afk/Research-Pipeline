That sequence did not fix the candidate set, the feature taxonomy, the source pages, the external model, or the exact dispatcher version. ## Z trial: complete recorded problem inventory

### Four defects in the initial research findings

1. **Deployment count:** the text said seven systems and eight deployments, while claims D-001 through D-009 and the sample table showed **nine**. Corrected to nine.
2. **Systems versus deployments:** a limitation said three of seven *systems* came from Lexzur. Only two systems did; three was Lexzur's deployment count. Corrected, but the brief had not explicitly defined this multi-deployment counting distinction.
3. **Sirion/Raiffeisen figures:** the original roughly 36,000 contracts across 14 countries came from a search snippet and was unsupported by the available case study. The live Sirion page returned HTTP 403. An Internet Archive capture showed 35,000 contracts and 12 countries; the findings were corrected and the archive/live-access limit disclosed. A later revalidator still disputed some counter and metadata details in the archived rendering, so exact page figures were not finally externally approved.
4. **Required non-AI treatment:** the findings covered search and analytics but omitted explicit rules and optical-character-recognition treatment. Rules were added; the report said OCR was **not documented in the fetched sources**, without claiming the products lack OCR. Z gap report (local test artifact: `scratch z/gap_report.md`) · validator result (local test artifact: `scratch z/runs/validation/dispatch/2db96148af844e478ce0f7c0fe65a765/result.json`) · Z deliverable (local test artifact: `test_reports/legal_ai_management_2026_prior_z.md`)

### Workflow, dispatcher, and output problems

5. **Model-ID intake mismatch:** the guide did not say that the recorded validator and gap-filler model answers had to exactly match configured IDs. The dispatcher did enforce exact equality; annotated answers, including an earlier record's style, would fail. The test normalized the recorded values. Z left project files unchanged.
6. **Narrated-output parser failure:** two complete DeepSeek validation attempts returned narration before JSON. The original parser insisted on stdout being exactly one JSON object and rejected both. Z correctly counted both dispatches as failures. A patched dispatcher copy under `scratch z/fixes/` accepted one complete role object within narration without weakening schema checks; the project's dispatcher was not changed during Z's test.
7. **Verdict contract could not express bounded uncertainty:** two fresh DeepSeek revalidations were rejected because an `approved` verdict accompanied an `unverifiable` check or an open issue. The record describes these as nonmaterial residual uncertainties, but the then-current schema had no valid “approved with labeled limits” state. The user chose reconciliation and disclosure rather than another Z-side patch. The residuals concerned Sirion archive-derived details and the interpretive basis for Contra's review/risk Yes cell. A rejected verdict is **not** external approval.
8. **Counting rule incompleteness:** the brief lacked a crisp systems-versus-deployments rule for vendors represented by several customers. The interview's cohort treatment resolved it during this run, but the gap exposed a reusable instruction ambiguity.
9. **Scratch visibility:** `scratch z/` was not gitignored and appeared untracked. It was retained at the user's direction for later removal.
10. **Missing timestamps in dispatch metadata:** old `dispatch.json` files had command/PID/exit/error but no start or finish time. Durations had to be reconstructed from file timestamps, to about one second.
11. **Word style distinction:** the corporate export passed user visual review, with layout/styling improvement notes. Academic and minimal looked almost identical; the report records a possible style consolidation. All three passed programmatic text/table/placeholder checks. `uv` was unavailable locally, so system Python with `python-docx` 1.2.0 was used. [Z defects table](LIVE_TEST_REPORT%20Z.md#defects-and-design-findings) · [Z timings](LIVE_TEST_REPORT%20Z.md#external-session-timings) · revalidation records (local test artifact: `scratch z/runs/revalidation/dispatch`)

### Evidence and coverage limits that Z explicitly retained

12. The target was 12 systems, roughly 8 GCC; Z found 7 systems and only 2 GCC systems/3 GCC deployments. The sample had no qualifying litigation-management or in-house matter-management system, and no GCC enterprise legal-department deployment. GCC evidence was concentrated in Lexzur products and UAE banks.
13. Searching from a US locale likely under-sampled Arabic-language GCC material; Z did not prove that all qualifying regional deployments had been found.
14. Every feature row contained Unknown statuses, so none qualified for the brief's universal/emerging/differentiating bands. Unknown means no explicit public vendor Yes/No, not feature absence. Feature descriptions came from vendor material and were not independently measured or proof of customer adoption.
15. Several vendor deployment pages were undated. Older dated accounts did not establish continued use at the 2026 cutoff. The live Sirion page's post-archive wording remained inaccessible; the archive-backed facts and one Contra risk classification remained bounded evidence questions. Only Lexa's sampled documentation named an underlying model basis.
16. The live trial was one interview on one machine and one research question. Its 10/10 workflow tests verified the implemented checks, not reproducibility of the market sample or final independent validation. ### Real validator and dispatcher failures after findings review

3. **First full validation, 12:08:** Mimo emitted complete `gaps_found` JSON with ten issues, but Windows Python decoded Docker's UTF-8 stderr using default `cp1252`. A `UnicodeDecodeError` was followed by a `TypeError` from missing decoded stderr. `dispatch.json` stayed `started`; the JSON was separately recovered and schema-checked. The failed dispatch was not retroactively counted as completed. The project dispatcher was changed to UTF-8 with replacement and exception recording.
4. **Gap-filler date error:** the successful Mimo gap filler described its live source checks as 1 October, but it ran on 2 October. The 1 October date was the research cutoff; eligible publication dates and saved earlier captures supported the research period. The false execution-date assertion shows that a schema-valid correction can still contain incorrect metadata.
5. **Full revalidation, 15:00:** the Docker/OpenCode process returned no result by the 900-second dispatch limit. Killing the Windows `docker exec` client left its OpenCode child running inside the container. It was discovered and stopped about 39 minutes after its start. That is a separate timeout-cleanup defect. Stage-scoped TERM/KILL cleanup was added and unit-tested, but not demonstrated in a later live timeout. The source of the slow model run itself was not established.
6. **First focused revalidation, 5:52:** Mimo exited successfully but returned `approved_with_limits` together with open issues; the schema correctly rejected the contradiction. Stdout contained competing JSON output and asserted checks on 1 October although the run occurred on 2 October. The narrowed input omitted URLs for unchanged claims, causing derived counts to be marked unverifiable in that pass. The prompt was later revised to distinguish research cutoff from check date and request one consistent object; a successful live result did not prove the revision.
7. **Second focused revalidation, at least 9:11:** even with complete source URLs, no verdict arrived by the user's extended cutoff. The exact Docker child was manually stopped; the automatic `dispatch.json` remained `started` and a separate manual-stop record captured failure. No stdout, stderr, or result JSON exists for that attempt. Provider latency, fetching, and analysis remain possible explanations; the orphaned full-revalidation child was concurrently running and is a plausible but unproven contributor.
8. **Final validation status:** none of Codex's four real validator activations produced a schema-valid approval of the corrected findings. The user reviewed the failure and chose a sourced report with explicit limits; the report was approved by the user but does **not** claim external validation. ## Why the same workflow yielded different reports and different failures

1. **The workflow is procedural, not a fixed research dataset.** Both briefs aimed at 12 eligible systems but allowed a smaller verified sample. Each originating agent independently discovered and screened candidates. Z selected Contra, the Lexzur platform, Sirion, Icertis, Luminance, Ironclad/NEXT, and Juro; Codex selected Lexzur, SpotDraft, LawVu, Leah, Pega, Brightflag, Ironclad/Signifyd, and Icertis/AkzoNobel. Shared vendor names do not make the sampled product or qualifying deployment identical. The feature taxonomy was explicitly derived from each source set, giving Z ten rows and Codex eight. Thus different counts can both follow the same instructions; they are not two measurements of one fixed cohort. Z brief (local test artifact: `scratch z/research_brief.md`) · Codex brief (local test artifact: `scratch/research_brief.md`) · both delivered matrices (local test artifact: `test_reports`)
2. **The confirmed decisions changed.** Z's cutoff was 30 September; Codex's was 1 October. Z explicitly defined the six GCC states and used a US-locale, English-first search with Arabic only when returned; Codex's plan called for English and Arabic country searches and a candidate register. Codex later accepted testimonial-grade Leah/Mashreq evidence through a renewed brief, raising its GCC and bank counts. Z did not have that rule or that selected testimonial. A one-day cutoff difference and undated live pages can change eligibility or available wording, but the records do not demonstrate that a specific vendor page changed overnight. Z plan (local test artifact: `scratch z/search_plan.md`) · Codex plan (local test artifact: `scratch/search_plan.md`)
3. **The validator models differed, and the DeepSeek probe outcome changed.** Z used DeepSeek for validation and Mimo for gap filling. Codex's same-route DeepSeek probe timed out at three minutes on the same trivial claim that Z's probe answered in ten seconds, then the user chose Mimo for both roles. There is no retained diagnostic proving a provider, network, quota, container, or model cause for that probe difference. The later long Codex validation timings belong to Mimo, so they cannot establish that “DeepSeek validation was slow under Codex.” Different model behavior is a credible contributor to different source interpretations, output formatting, and runtime, but this pair of runs does not isolate a model effect experimentally. probe dispatches (local test artifact: `scratch/delegate_runs/probe/dispatch/fc4c1573b769400caa0c43e295ffb097/dispatch.json`) · Z probe (local test artifact: `scratch z/runs/probe/dispatch/fd4a367c231a47ddbaa015af28120d53/dispatch.json`)
4. **The code and role contract changed between trials.** Z's first two outputs encountered the strict parser; Z patched a copy only in its scratch directory. Codex incorporated a narrated-object parser into the project, so that particular failure did not repeat. Codex then exposed Windows stderr decoding and orphan cleanup defects that the Z run did not trigger. The `approved_with_limits` state added after Z allowed a new *kind* of result, but Codex's model returned it inconsistently with open issues. The two tests therefore exercised different dispatcher states, not an unchanged binary. [Z defect record](LIVE_TEST_REPORT%20Z.md#defects-and-design-findings) · [Codex changes](LIVE_TEST_REPORT_CODEX_A.md#project-changes-and-checks)
5. **Source access and extraction differed.** Z had an HTTP 403 on Sirion and had to rely on an archive; Codex's sources included a LinkedIn participant comment, hidden/collapsed FAQ text, and an AkzoNobel PDF with difficult font encoding. These create different opportunities for missed evidence, ambiguous qualification, extra tool calls, and inconsistent checking. For example, Codex's focused Mimo log shows many live `WebFetch` calls and attempts to process the PDF in a container without common PDF/Python utilities. This documents extra work in that run, although the logs do not allocate each minute to fetching, model thinking, or provider wait. The number of findings defects reflects the substance of each draft and what that model noticed, not simply file length. ## What remains unresolved across both tests

- Neither trial ended with a schema-valid final independent approval of the corrected findings. Their delivered reports should be read with their disclosed evidence limits, not described as externally validated.
- The Codex DeepSeek probe's three-minute timeout and the long Mimo validation runs have no provider-level or per-tool timing diagnosis in the retained records. The Docker orphan is demonstrated; its contribution to later latency is not.
- The live behavior of Codex's stage-scoped Docker timeout cleanup and revised date/verdict prompt was not tested successfully after the changes. Direct host OpenCode remains untested, and Antigravity's source-read permission remains blocked in this installation.
- The exact final external status of archive-derived Sirion numeric detail and Contra's risk/review classification in Z remains bounded by the rejected revalidation verdicts. Codex's Leah/Mashreq classification is a user-approved testimonial threshold with limited public deployment detail.
- Both comparisons are purposive, under target size, source-dependent, and too different in sample and function taxonomy to treat their Yes counts as a controlled before/after accuracy or speed benchmark.
