## Batch A — Intake and result values

Locations: scripts/check_intake.py, scripts/research_dispatch.py and focused regression tests.

Replace string-coercion completeness checks with explicit validation of the documented answer representation. Require nonempty strings for answered decisions and not_applicable reasons. Reject null, missing values, whitespace, booleans, numbers and containers. Preserve valid strings such as an explicit optional “none,” existing enumerations, branch resolution and exact-brief confirmation.

Require result objects, summaries, lists and their items to have documented types. Validate change, unresolved and limitation entries, not just their containing lists. Reject source_urls as a string where a list is required and invalid members inside a source list. Preserve multiple sources and justified unresolved entries.

For web locators, require usable HTTP(S) syntax including a host; reject executable schemes and malformed values. Do not fetch sources inside the schema checker or confuse syntax with support. Preserve supplied-document citations. Inventory valid existing document representations before tightening checks. Prefer validating them; add a small explicit document-locator alternative only if needed to distinguish real citations from arbitrary text. If that requires substantial migration, present it separately for approval.

Acceptance: reproduced null/malformed cases fail; valid intake/results, “none,” document citations, multiple sources and explicit uncertainty pass. Exact-byte confirmation and nonmaterial-limit rules continue working.

## Batch C — Input-bound coverage

Locations: scripts/research_dispatch.py, affected callers in scripts/research_mailbox.py and tests/manual_live_dispatch.py, and relevant delegation guidance.

Keep existing Markdown inputs. Identify record IDs from supported legacy headings/record lines without treating prose references, tables or fenced examples as new claims. Do not impose numeric suffixes or one mandatory heading grammar on every user.
