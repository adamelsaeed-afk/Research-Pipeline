# Research Pipeline V1.1 Test Report

Test date: 9 October 2026, Africa/Cairo. Version: **V1.1**, as identified by the skill author. Tested project: `D:\Research skill`. Evidence root: `test_reports/live_legal_ai_2026-10-09`.

## Verdict

**Partial pass.** V1.1 completed the selected research route from interview to a reviewed Markdown report and Word document, but required manual recovery, independent contract checks and an output pagination repair. It did not reliably enforce all its intended requirements automatically.

The interview and exact-brief confirmation worked. Initial external validation caught research errors. A focused gap-filling retry and fresh validation produced supported, qualified findings. Four negative probes exposed incomplete deterministic enforcement. The unchanged Word exporter produced a split matrix row. The final document was repaired locally and every page was inspected; the exporter defect remains open in V1.1.

This report records all currently known shortcomings identified by this trial and its associated code review. One bounded trial cannot establish that no other defects exist. No implementation fixes have been made. The author approved adding this report to Documentation and requested a separate implementation plan; that request does not approve implementing the plan.

## Current shortcomings

### S01 Required intake answers can be null

**Reproduced negative-test defect.** A required geography decision with state answered and JSON null passed check_intake.check. The checker evaluates `str(answer).strip()`; Python None becomes the nonempty string `None`. The same coercion pattern is used for not-applicable reasons. It also does not establish that arbitrary populated values have appropriate answer types. The actual live geography answer was explicit, so this probe did not corrupt the final brief.

Consequence: a structurally incomplete decision can pass the gate despite the intended requirement for resolved, meaningful recorded answers. The exact-byte confirmation gate worked; this defect concerns field completeness, not hash verification. [Code](<D:/Research skill/scripts/check_intake.py:60>), [probe results](<D:/Research skill/test_reports/live_legal_ai_2026-10-09/evidence/contract_probes.json>).

### S02 Approval is not checked against the original claim set

**Reproduced contract defect.** The result checker accepted an approved result covering only C1 of hypothetical C1/C2 input. It also accepted a checked identifier ABSENT that hypothetically did not belong to the input. It compares checked_claim_ids with the IDs inside the returned checks, not the original findings; validate_result receives no expected input-ID set.

Consequence: internally consistent partial or invented coverage can pass the deterministic result check. The final live result did not exhibit either behavior: the operator independently compared all C1-C14 with returned IDs and evidence checks, and found exact coverage. [Code](<D:/Research skill/scripts/research_dispatch.py:197>), [coverage audit](<D:/Research skill/test_reports/live_legal_ai_2026-10-09/evidence/revalidation_coverage_audit.json>).

### S03 Source and related result fields are incompletely typed

**Reproduced contract defect.** A gap-fill source_urls field containing a plain non-URL string passed because the checker requires a populated value rather than a correctly typed list of usable locators. The live focused corrections supplied lists that the operator checked directly.

Related **static code-review gaps**, not additional executed negative tests: source_url is checked as nonempty text without URL/locator validation; gap-fill unresolved entries have no per-item schema check; gap IDs are not matched against supplied gaps; duplicate checked IDs collapse in set comparisons; issues require id/problem but do not enforce their full documented claim/source fields; summary uses the same string-coercion pattern as intake. These related paths need regression cases before being called verified defects or fixed behavior. [Code](<D:/Research skill/scripts/research_dispatch.py:212>), [gap result checks](<D:/Research skill/scripts/research_dispatch.py:249>).

Consequence: populated, internally consistent output can be accepted without establishing correct types, input identity or usable citations. Syntactic locator validation would still not prove that a cited source supports a finding; evidence reading remains required.

### S04 Broad gap filling did not finish within its deadline

**Observed live execution failure.** The first substantive gap filler performed extensive source work but returned no final object within 600 seconds. Elapsed time was 602.268 seconds including cleanup. stdout was empty; stderr retained tool activity. The dispatcher correctly recorded failed, exit 143 and timeout_cleanup matched=1, with no result.json. A focused fresh retry addressing the same five issues completed.

Consequence: the broad request needed operator narrowing to achieve a usable result. Missing container tools consumed effort, but one definitive cause of the timeout cannot be established. Raising the timeout alone would not address scope drift or unbounded investigation. Failed output cannot be treated as approval. [Failure metadata](<D:/Research skill/test_reports/live_legal_ai_2026-10-09/runs/gap_fill/dispatch/97f9b855780a4cb3865fc5753f3cc257/dispatch.json>).

The container lacked ps, Python 3 and Node; attempts using Python 3 failed. A read-only /proc inspection found no former research OpenCode/curl/bash process after cleanup. Cleanup worked in this observed run; the trial does not establish cleanup behavior for every child-process arrangement.

### S05 Word export can split a feature row across pages

**Observed export defect.** The unchanged corporate exporter produced four pages. Its first matrix body row split across pages 3 and 4, separating the feature name from Advanced-tier and Archie qualifiers. Repeating headers worked, but rows lacked cantSplit and the surrounding table content did not travel together.

The original DOCX, PDF and all four baseline images were preserved. A test-local repair added non-splitting rows and kept table headers and preceding captions with subsequent content. The first repair left an orphan header and was rejected. The final five pages were rendered and all inspected; text and hyperlinks matched the baseline exactly. No exporter source was changed. The final artifact passed inspection after repair; the unchanged V1.1 exporter did not pass this pagination check. [Original DOCX](<D:/Research skill/test_reports/live_legal_ai_2026-10-09/evidence/AI_LEGAL_MANAGEMENT_REPORT_EXPORT_BASELINE.docx>), [baseline page 3](<D:/Research skill/test_reports/live_legal_ai_2026-10-09/evidence/export_baseline_page-3.png>), [baseline page 4](<D:/Research skill/test_reports/live_legal_ai_2026-10-09/evidence/export_baseline_page-4.png>), [repair audit](<D:/Research skill/test_reports/live_legal_ai_2026-10-09/evidence/artifact_pagination_repair.json>).

### S06 Export QA depends on available renderers

**Observed environment limitation.** The packaged document renderer failed under Windows sandbox temporary-directory permissions. Approved execution outside the sandbox then exposed the actual missing prerequisite: LibreOffice soffice.exe was absent from PATH. Installed Microsoft Word rendered the document invisibly instead, followed by bundled Poppler images. This was an alternate QA route, not a successful packaged-renderer run.

Poppler emitted Symbol/ArialUnicode display-font warnings; inspected pages showed no missing glyphs. V1.1's guidance does not provide a complete portable renderer fallback or a deterministic visible-pagination check. A machine that cannot render must report that limit rather than assert visual success. [Renderer failure](<D:/Research skill/test_reports/live_legal_ai_2026-10-09/evidence/renderer_actual_unsandboxed.txt>), [visual review](<D:/Research skill/test_reports/live_legal_ai_2026-10-09/evidence/word_visual_review.md>).

### S07 Model-generated audit precision is not independently reliable

**Observed minor audit errors.** The focused gap filler assigned the same exact retrieval minute to all source checks without independent timestamps supporting that precision. The operator retained only the established date and dispatch interval. The final validator summary claimed 16 source URLs; structured checks contained 18 unique URLs and 19 checks including the derived totals.

Consequence: free-text counts and precise timestamps require independent reconciliation. These discrepancies did not alter a final research claim. Successful JSON parsing and a verdict do not verify narrative metadata.

### S08 Fresh sessions do not constitute filesystem isolation

**Observed execution boundary.** Roles read dispatch metadata, prompts or logs in addition to their brief and role input. Source recovery used /tmp/opencode, and OpenCode used its global tool-output location. Selected public source files were copied into evidence; the remaining trail is in logs. Originating search reasoning was not supplied in the role inputs.

Consequence: fresh processes and minimal staged research inputs reduce contextual exposure, but do not enforce a filesystem boundary or place every generated file inside the test directory. The wording that roles read only brief/input is stronger than the observed execution. This is not proof that originating search history contaminated validation. Credentials or unrelated private files were not needed for the research.

### S09 Correct results still require semantic oversight

**Observed dependency on review, with intended recovery.** The originating first findings used stale Clio metadata and unsupported subscription-tier wording from older search-result content. Initial validation caught both. Material corrections distinguished HTML edits from API updates, limited Clio time assistance to suggestions, added Clio Grow screening, and excluded Smokeball AutoTime beta descriptions.

Smokeball intake sources did not establish qualifying non-beta US availability. It remained explicitly unknown; the already confirmed interview policy settled its treatment. Approval of a supported uncertainty statement is not approval of release availability. The result contract cannot by itself establish source entailment, uncover every unrecorded interview branch, or prove complete vendor inventories.

### S10 External runtime and host instructions affect reproducibility

**Observed environment limits.** OpenCode changed from 1.18.34 at initial inspection to 1.18.35 at preflight. The skill snapshot was frozen, but its external runtime was not. Existing unit tests initially encountered 12 sandbox temporary-directory permission errors; all 16 passed outside the sandbox. Export dependency setup initially hit sandbox DNS restrictions, then succeeded with approved escalation. uv was invoked as a Python module because its executable was absent from PATH.

Agent Reach was used because separate session-level Agent Reach instructions mandated it for internet research. V1.1 does not require Agent Reach installation or that backend. Exa was unavailable; built-in web search/direct official reads and a retained MyCase Jina retrieval were used. This trial must not be interpreted as adding an Agent Reach dependency to the research skill.

### S11 Development guidance and evidence publication can drift

**Static documentation limitation.** Historical INSTRUCTIONS.md includes earlier activation-gate, methodology, adoption and prescriptive-report wording that differs from the current SKILL.md and later revision decisions. Existing historical plans also describe models and verification statuses for their own trials. They are not current execution instructions for this author's no-DeepSeek trial.

Consequence: an implementing agent must distinguish historical specifications and trial reports from the active workflow and current human instructions. It must not silently restore older behavior. The installed skill is also a separate older copy; updating repository files will not by itself update that installation. Finally, ignored local evidence links in published Documentation are local audit references, not public downloads.

### S12 Coverage is limited to the route exercised

**Verification limit.** This trial exercised one market-feature route, a fixed sample, Docker OpenCode, comprehensive English reporting and corporate Word output. Same-session review, host CLI, host-bridge arrangements, technical research, market sizing, other templates and later refinements were not executed in this trial. Prior trial reports may supply historical evidence for some routes, but they are not fresh V1.1 verification here. Native interviews used simulated stakeholders and did not test real sponsor behavior.

The passing 16-test suite did not cover the four reproduced contract/completeness failures or visible Word pagination. It cannot be cited as proof of those requirements. Repeating the same Mimo model in fresh processes also does not test agreement across independent model families.
